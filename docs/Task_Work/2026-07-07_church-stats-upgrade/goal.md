# Goal — 교회 현황(통계 인사이트) 섹션 고도화

> 2026-07-07 · 심층 리서치(코드베이스 + 해외/국내 ChMS 사례) 기반 제안. 상세: `detail_goal.md`, 자산 조사: `analysis.md`

## 목표

교회 관리의 한 탭(`/church?tab=overview`)에 묻혀 있는 "현황"을 **독립 현황 섹션**으로 승격한다.

- 진입: 사이드바 "운영" 섹션 → 현황 클릭 시 **오버뷰 페이지**(`/{slug}/stats`)
- 하위: 도메인별 서브페이지 — 출석 / 말씀 암송 / 말씀노트 / 재정 / 교적
- 설계 원칙 3가지:
  1. **집계표가 아닌 행동 연결형 인사이트** — 오버뷰 하단은 "이번 주 해야 할 일"(48시간 팔로업, 연속 결석, 스트릭 끊김)로 끝난다
  2. **숫자에서 사람으로** — 모든 KPI는 명단 → 개인 프로필 → 액션(심방 배정·연락)까지 3단계 드릴다운
  3. **역할이 화면을 결정** — 같은 URL이라도 `my_role()`/`module_grants`에 따라 위젯 조립이 달라진다 (재정은 giving 게이트 안에서만)

## 왜

1. 국내 교적 프로그램(온맘·스데반 등)은 "몇 명인가" 집계표에 머묾. 해외 제품의 3대 인사이트 패턴 — ① 이탈위험 조기 감지→심방 연결, ② 새가족 정착 퍼널 전환율, ③ 신앙습관 스트릭 — 을 한국 교회의 심방·교구 문화와 결합하는 것이 ChurchThrive의 차별화 기회.
2. 기록하는 곳(출석 체크·헌금 입력·암송 체크)과 읽는 곳(현황)을 분리하면 당회/제직회 보고 전 한 곳만 도는 동선이 됨.
3. 홈 고도화 로드맵(개인/할 일 중심)과 상보적 — 홈은 "나의 오늘", 현황은 "교회 전체의 추세".

## 완료 기준 (DoD) — Phase 1 기준

**기준선**: 타임존 KST(Asia/Seoul), 주간 단위 = **일요일 시작**(교회 주일 기준, `date_trunc` 주 시작 보정 필수). 집계 RPC 응답 **p95 < 1s** (시드 규모 기준 측정).

- [ ] `/{slug}/stats` 오버뷰: KPI 스트립(전주 대비 증감) + 13주 추세(4주 이동평균) + "이번 주 해야 할 일" 액션 리스트 — 역할별 노출은 아래 매트릭스대로
- [ ] **역할별 KPI/접근 매트릭스 검증** (역할별 계정으로 실측):

  | 역할 | 오버뷰 KPI | `stats/attendance` | `stats/members` | 스코프 |
  |---|---|---|---|---|
  | superadmin | 주일 출석·새가족·암송 참여율·심방 필요·재적/활동·주간 헌금 | ✅ | ✅ | 교회 전체 |
  | pastor | 위와 동일하되 **주간 헌금 카드 비노출** — 담임목사(대표 교역자) 또는 giving grant(viewer+) 보유 시에만 노출 | ✅ | ✅ | 교회 전체 |
  | dept_leader | 자기 부서 출석·심방 필요만 | ✅ (자기 부서 필터 고정) | ✅ (자기 부서만) | `my_led_departments()` |
  | checker | 출석 KPI만 | ✅ (읽기) | ✕ | 교회 전체(출석만) |
  | member | 접근 불가 | ✕ | ✕ | — |

- [ ] **비인가 접근 차단 기준**: member/checker가 비인가 `stats/*` URL 직접 접근 시 기존 `church/page.tsx:13` 패턴대로 `/{slug}/home` 리다이렉트 (데이터 응답 자체가 없어야 함 — RPC가 빈 jsonb 반환, RLS 계층 차단). 테스트 시나리오: ① member→`/stats`, ② checker→`/stats/members`, ③ dept_leader→타 부서 파라미터 조작 시 자기 부서로 강제
- [ ] 서브페이지 `stats/attendance`, `stats/members` 동작 (예배별·부서별 분해, YoY 비교 — 교적 전출입 YoY는 `audit_log` 데이터 존재 구간만 표시하고 이전 구간은 "데이터 없음" 명시)

- [ ] 사이드바 "운영"에 "교회 현황" + 하위 항목 (`registry.ts` children 패턴), 기존 `?tab=overview`는 새 오버뷰로 리다이렉트
- [ ] 집계 RPC 신설 (`stats_overview()` 등) — `home_feed()` 패턴: 역할/모듈 게이트 내장, 1왕복, p95 < 1s
- [ ] **뷰포트 기준**: 중단점 768px(기존 `md:` 기준) — ≥768px 사이드바 웹 레이아웃(`md:pl-60`), <768px 1열 카드 스택. 375px(모바일)·768px·1280px 3개 폭에서 가로 스크롤 없음 확인

## 가정 / 의존성 / 리스크

### 가정
- 중소형 교회 규모에서 실시간 집계 쿼리로 충분 (초기 materialized view 불요)
- `attendances`/`members`/`mod_verse`/`mod_giving` 스키마는 Phase 1~3 동안 안정적
- 통계 열람 권한은 기존 역할 체계(`app_role` + `module_grants`)로 표현 가능 — 신규 역할 불요

### 의존성
- `home_feed()` RPC 조립 패턴 (`00025_home_feed.sql`) — 신규 stats RPC의 템플릿
- `attendance_trend()`, `absentee_list()`, `verse_current()`, `admin_list_departments()` 기존 RPC
- `TrendChart`(SVG), `Stat`, `.card`, 진행바 등 기존 컴포넌트 (`analysis.md` §5)
- **mod_verse는 Family_Verse로 소유권 이전 예정** — 암송 통계는 반드시 RPC 경계 뒤에 배치해 소스 교체에 대비

### 리스크 & 대응
- **재정 데이터 노출 사고**: 재정 지표는 UI 조건분기가 아니라 RPC/RLS 계층에서 차단. 메뉴 노출 자체를 `has_module('giving')`로 게이트
- **참여 점수의 낙인 효과**: 개인 노출 금지, 목회자 화면에서도 "심방 후보"로만 표현 (등급 라벨 비노출)
- **교적 증감 추이의 소급 한계**: `audit_log`(`members_audit` 트리거)는 가동 시점 이후만 기록 — 그 이전 전출입은 소급 불가. 해당 구간은 "데이터 없음"으로 정직하게 표시 (`analysis.md` §3-5 재분류)
- **집계 성능**: 세그먼트 계산이 느려지면 주간 배치/materialized view로 전환 (경계: p95 1s)
