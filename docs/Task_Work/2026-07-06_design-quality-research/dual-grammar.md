# 웹/앱 문법 혼재 재분석 — 이원 문법(Dual Grammar) 체계 제안

> 2026-07-06 사용자 진단: "웹도 아니고 앱도 아니다" — 정확함. 원인과 해법.

## 1. 진단 — 무엇이 섞여 있나 (코드 실측)

| 화면 | 현재 상태 | 문제 |
|---|---|---|
| 교인 홈/교적/모듈 | 관리자와 같은 사이드바 셸(md:pl-60) 안에 max-w-lg 좁은 컬럼 | 데스크톱에서: 어드민 사이드바 + 앱 폭 콘텐츠 = 정체불명. 교인에게 사이드바는 과잉 |
| 관리자 명부/플랫폼 | 데스크톱 웹 어드민 문법 (테이블·서브메뉴·⌘K) | 모바일에서 테이블·10개 서브메뉴가 그대로 축소 — 웹을 구겨 넣은 형태 |
| 모바일 내비 | 상단바 + 하단 탭(신규) + 페이지별 칩 | 세 가지 내비 문법 공존, check/scan은 탭바 숨김 — 규칙이 화면마다 다름 |
| 온보딩/초대 | 중앙 카드 (모바일 문법) | 유일하게 일관됨 — 이 문법이 옳았음 |

**근본 원인**: "반응형 하나로 모두 커버" 전제. 그러나 우리 세계관은 **서로 다른 두 사용자가 서로 다른 기기에서 서로 다른 일**을 한다:
- 교인(시니어 다수) = 폰, 소비·확인·1탭 행동 → **앱 문법**이어야 함
- 운영자(관리자·교역자·담당자) = 데스크톱/태블릿, 관리·일괄 작업·밀도 → **웹 문법**이어야 함

## 2. 해법 — 이원 문법 체계 (Dual Grammar)

레퍼런스: 토스(앱 서비스의 웹 = 모바일 폭 중앙 고정), Linear/Slack(어드민 = 데스크톱 우선), 카카오워크(구성원 앱 / 관리자 웹 완전 분리)

### 문법 A — "앱" (교인 공간: home·me·menu·m/*·invite·join)
- 모든 뷰포트에서 **모바일 폭(max-w-md) 중앙 컬럼** — 데스크톱에서도 사이드바 없음, 앱을 크게 보는 것
- 내비 = **하단 탭 바 단일** (데스크톱에서도 하단 고정 or 컬럼 하단) + 상단은 타이틀만
- 카드·풀스크린 시트·큰 버튼, hover 의존 없음, 리스트는 무한 스크롤
- 시니어 규격이 1급 (17px+·48px+·글자 토글)

### 문법 B — "웹 어드민" (운영 공간: church·platform·invites·members/[id]·store)
- 데스크톱 우선: 사이드바 + 서브메뉴 + 테이블 + ⌘K + 밀도 (현행 유지·강화)
- **모바일 = 축소가 아니라 "당직 모드"**: 자주 쓰는 과업 4개(가입 승인·초대·미출석 확인·검색)만 카드형으로, 나머지는 "데스크톱에서 이용해주세요" 안내
- 진입: 교인 앱 하단 탭에는 넣지 않음 — 메뉴 페이지의 "운영 도구 열기"로 컨텍스트 전환을 명시 (플랫폼 D2 패턴을 교회 관리에도)

### 문법 C — "키오스크" (현장 태스크: check·scan)
- 태블릿 풀스크린 전용: 내비 최소(나가기만), stat-strip 유지, 탭바 없음 (현행이 이미 옳음 — 명문화)

### 전환 규칙
- 로그인 직후: 역할 무관 **문법 A 홈**으로 (관리자도 교인임 — 세계관의 누적 원칙 유지)
- 운영 진입 = 명시적 컨텍스트 전환 (버튼 → 문법 B 공간, "교회로 돌아가기"로 복귀) — 플랫폼 콘솔에서 검증된 패턴의 일반화
